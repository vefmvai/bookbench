# BookBench

> **Фреймворк для написания больших связных текстов — книг, монографий, диссертаций, научпопа — поставляемый как плагин Claude Code.**

## TL;DR

BookBench разворачивает в папке вашей книги команду из девяти специализированных субагентов: стратег планирует главу, писатель пишет, фактчекер проверяет, редактор правит, маркетолог упаковывает. Каждый — в изолированном контекстном окне, с собственной памятью и набором правил. Жанровая методология подбирается под книгу. Голос автора живёт в библиотеке между книгами. Опен-сорс. Под Claude Code 2.x.

> *One-liner:*
> **Команда субагентов под ролями превращает папку книги в верстак (workbench), на котором пишется большой нон-фикшн-текст.**

## Что это

**BookBench** — это **фреймворк**, поставляемый как плагин для Claude Code. Аналогия: Rails — это фреймворк, который доставляется как Ruby gem. Здесь — точно так же: то, что вы устанавливаете командой `/plugin install`, — это плагин; то, как вы потом работаете, — это методология, процесс и команда субагентов под единой ролью «команда вашей книги».

Знакомая картина: у автора нон-фикшн-книги в `claude.ai web` — половина рукописи в чатах, в Obsidian — десятки заметок, в облаке — три недописанных файла. Веб-версия упирается в лимиты контекста, теряет состояние между сессиями, не помнит, какие примеры уже использованы, не отделяет голос писателя от стилистики ИИ. BookBench для тех, кто упёрся в этот потолок и хочет перенести работу в Claude Code — с инструментом, который превращает папку книги в полноценную среду: команду ролей, файловый протокол, реестры памяти, гейты автора в нужных точках.

Главная идея — **команда субагентов под ролями**, а не один универсальный «помощник, который умеет всё». Стратег не размывается на стиль, фактчекер не отвлекается на голос, редактор не лезет в маркетинг. Каждая роль — отдельная ментальная модель, отдельный контекст, отдельные права на инструменты. Они говорят между собой через файлы (`spec.md → draft.md → factcheck.md → edited.md → marketing.md`), а не через общую память. Это не выбор стиля — это архитектурное следствие платформенного ограничения Claude Code (субагент не может вызвать другого субагента), превращённое в преимущество: изоляция контекстов даёт качество, недостижимое одним «универсальным» агентом.

## Для кого

**«Научпоп-первый универсальный»** — авторы нон-фикшн-книг с фокусом на научпоп.

**Типичный пользователь:**

- Уже пишет нон-фикшн — научпоп, нарративный нон-фикшн, монографию, диссертацию, deep-dive статью.
- На старте имеет «багаж»: половину книги в чатах, заметки в Obsidian, черновики глав в `.docx`, фрагменты по разным папкам. Сценарий «с чистого листа» — редкость; реальный кейс — собрать наработанное и продолжить, не теряя ничего.
- Работает локально: терминал, файловая система, git. Не хочет переносить рукопись в SaaS.
- Пишет на русском (приоритет 0.1).

**Не для:**

- Тех, кто ищет «ИИ, который напишет книгу за меня» (autonomous single-shot инструменты — антипод).
- Тех, кому нужен fiction-генератор romance/thriller (Sudowrite, NovelCrafter — другая ниша).
- Тех, кому нужен чисто academic publishing tool с заточкой под цитирование и форматирование журналов.

## Как это работает

### Трёхуровневая архитектура

BookBench разделяет три уровня данных, чтобы обновление кода плагина никогда не задевало вашу книгу:

```
┌────────────────────┐    ┌────────────────────┐    ┌────────────────────┐
│ КОД ПЛАГИНА        │    │ ДАННЫЕ ПЛАГИНА     │    │ ПАПКА КНИГИ        │
│ ${CLAUDE_PLUGIN_   │    │ ${CLAUDE_PLUGIN_   │    │ my-book/.book/     │
│  ROOT}             │    │  DATA}             │    │                    │
│                    │    │                    │    │                    │
│ команды, шаблоны,  │    │ реестр книг,       │    │ ваш контент,       │
│ скиллы, дефолты    │    │ глобальные         │    │ гайдлайны команды, │
│ жанров             │    │ настройки,         │    │ реестры памяти,    │
│                    │    │ история Evolver    │    │ главы              │
│                    │    │                    │    │                    │
│ стирается при      │    │ переживает         │    │ собственность      │
│ /plugin update     │    │ /plugin update     │    │ автора, не         │
│                    │    │                    │    │ трогается обновл.  │
└────────────────────┘    └────────────────────┘    └────────────────────┘
```

Полная схема со всеми стрелками и контрактами — в [`docs/architecture.md`](docs/architecture.md).

### Команда из девяти субагентов

| Роль | Ответственность | Артефакт |
|------|-----------------|----------|
| `book-coordinator` | Оркестратор: вызывает остальные роли, держит общее состояние | (главный диалог) |
| `book-strategist` | Планирует главу, формирует ТЗ, ведёт реестр концепций | `spec.md` |
| `book-writer` | Пишет драфт по ТЗ, удерживает голос автора | `draft.md` |
| `book-factchecker` | Проверяет факты с claim-provenance тэгами | `factcheck.md` |
| `book-editor` | Правит стиль, связность, длину | `edited.md` |
| `book-marketer` | Упаковывает финал в посты, обложку, фрагменты | `marketing.md` |
| `book-doc-classifier` | Разбирает существующие материалы по типам | (импорт) |
| `book-doc-synthesizer` | Собирает классифицированные фрагменты в структуру книги | (импорт) |
| `book-tuner` | Анализирует замечания автора, предлагает правки гайдлайнов | (опционально) |

Каждая роль работает в изолированном контекстном окне через нативный механизм Claude Code (`Task` tool). У каждой роли — собственный `tools`-allowlist (фактчекер не может править текст; писатель не имеет WebSearch), своя инжекция `skills:` (методология подгружается автоматически), своя `memory: project` (реестр уникальности на роль) и при необходимости свои `hooks` (анти-ИИ-клише lint после каждого Write писателя и редактора).

### Микро-цикл главы — пять фаз

Сердце фреймворка. Команда `/book:write-chapter <N>` запускает цепочку из пяти фаз с двумя гейтами автора и двумя петлями верификации:

```
spec.md (стратег)
   ↓
   ✋ автор подтверждает ТЗ
   ↓
draft.md (писатель)            ← hooks: anti-ai-cliche-lint после каждого Write
   ↓
factcheck.md (фактчекер)       ← loop: writer revise при BLOCKER (макс. 3 итерации)
   ↓
edited.md (редактор)           ← двойной audit-pass; loop: фактчекер re-check
   ↓
marketing.md (маркетолог)
   ↓
summary.md (автогенерация)
   ↓
   ✋ финальный обзор главы
```

Внутри пяти фаз — полностью автономно. Гейты автора срабатывают только в двух точках цикла: после `spec.md` (утверждение ТЗ) и после `marketing.md` (финальный обзор). Это снимает с автора когнитивную нагрузку «вручную переключать роли», характерную для работы в `claude.ai web`. Полный гайд по циклу — в [`docs/chapter-cycle.md`](docs/chapter-cycle.md).

### Голос автора

`book-writer` не начнёт писать `draft.md`, пока не заполнен `voice-profile.md` — короткое описание прозы плюс шесть параметров (формальность, длина абзаца, разнообразие предложений, эмоциональная интенсивность, тип тире, толерантность к англицизмам). Голос строится одним из трёх способов: быстрое интервью на 5 минут прямо в текущей сессии, отдельная серьёзная сессия с пробным абзацем (`/book:voice build`) или агент сам предлагает на основе плана книги.

Голос — переиспользуемая сущность. Один автор пишет несколько книг — голос сохраняется в личной библиотеке `~/.bookbench/voices/` (вне плагина и вне папки книги) и переносится между книгами через `/book:voice save-as` / `/book:voice import`. Подробности — в [`docs/voice-management.md`](docs/voice-management.md).

## Быстрый старт

```bash
# 1. Установить плагин (через стандартный механизм Claude Code)
/plugin install bookbench

# 2. Создать папку для книги
mkdir my-book && cd my-book
claude

# 3. Запустить установочное интервью внутри Claude Code
> /book:start
```

После `/book:start` команда задаст несколько вопросов (жанр, рабочее название, аудитория, объём, два стартовых сценария — см. ниже) и развернёт в папке всё нужное: `.book/PROJECT.md`, `.book/ROADMAP.md`, шаблоны 9 субагентов в `.book/.claude/agents/`, гайдлайны, hooks, реестры памяти. Дальше — `/book:plan-book`, `/book:plan-chapter 1`, `/book:write-chapter 1`.

Полный пошаговый прогон «первые 30 минут» — в [`docs/quickstart.md`](docs/quickstart.md).

## Команды первой необходимости

Из 40+ команд, поставляемых с плагином, эти десять покрывают 90% повседневной работы:

| Команда | Что делает |
|---------|------------|
| `/book:start` | Установочное интервью; разворачивает структуру книги |
| `/book:status` | Текущее состояние книги: на какой главе, сколько готово |
| `/book:next` | Что делать следующим шагом (умная подсказка по workflow) |
| `/book:plan-book` | Стратег предлагает план книги (chapter list) |
| `/book:plan-chapter <N>` | Стратег пишет ТЗ главы → `spec.md` |
| `/book:write-chapter <N>` | Полный 5-фазный цикл главы (writer → factcheck → edit → market) |
| `/book:tune` | Tuner анализирует замечания и предлагает правки гайдлайнов |
| `/book:voice build` | Отдельная сессия для построения профиля голоса |
| `/book:audit-book` | Аудит всей книги (red thread, cross-references, ИИ-клише) |
| `/book:help` | Полный список команд с описанием |

Полный каталог — `bookbench/manifest.json` и `bookbench/commands/`. См. также [`docs/customization.md`](docs/customization.md), [`docs/upgrade-guide.md`](docs/upgrade-guide.md).

## Два стартовых сценария

BookBench принимает автора с любого старта — это сквозное требование архитектуры:

- **Сценарий A — с чистого листа.** У вас есть только идея и пустая папка. `/book:start` задаст вопросы, развернёт пустые реестры, поможет построить план и голос с нуля. Полный путь — раздел A в [`docs/quickstart.md`](docs/quickstart.md).
- **Сценарий B — с существующих материалов.** У вас уже есть половина книги в чатах `claude.ai`, заметки в Obsidian, черновики в `.docx`. `/book:start --from-existing` запускает оркестратор импорта: классификатор разбирает фрагменты по типам (idea, draft, fact, metaphor, ...), синтезатор собирает их в структуру книги, реестры памяти стартуют пополненными. Дальше микро-цикл главы работает в режиме «дополнения», а не «с нуля». Полный путь — раздел B в [`docs/quickstart.md`](docs/quickstart.md).

В обоих случаях после установки команда субагентов одна и та же, файловый протокол один и тот же, микро-цикл главы один и тот же. Разница — только в стартовом состоянии реестров и режиме `book-writer`'а.

## Совместимость

- **Claude Code:** `^2.0` (сервис команд, скиллов, субагентов, hooks). Поле `compatible_claude_code` в `manifest.json`.
- **Подписка Claude:** работает на любом тарифе. Рекомендации по выбору профиля моделей под Pro / Max-5x / Max-20x — в [`docs/models-and-subscriptions.md`](docs/models-and-subscriptions.md). На Pro используйте профиль `budget`, чтобы не выжигать дневной лимит Opus за две главы.
- **Платформа:** macOS, Linux, Windows (через WSL для bash-hooks).

## Дорожная карта 0.1 → 0.2+

**Что в 0.1 готово:**

- 9 субагентов (5 микро-цикла + 2 импорта + tuner + координатор) с боевыми системными промптами.
- 40+ slash-команд (онбординг, планирование, написание, аудит, голос, эволюция).
- Микро-цикл главы с loop verification и гейтами.
- Анти-ИИ-клише hook (46 паттернов: 34 английских + 12 русско-специфичных) с тремя уровнями реакции (block / warn / info).
- Реестры памяти через `memory: project` per role с двухуровневой компакцией.
- Жанровый скилл-ресёрчер для on-demand методологий новых жанров.
- Импорт чатов `claude.ai`, заметок, `.docx` через классификатор и синтезатор.
- Личная библиотека голосов `~/.bookbench/voices/` с пятью командами `/book:voice *`.
- Три профиля моделей (`budget` / `balanced` / `quality`) под разные планы Claude.

**Известные ограничения 0.1.0** (известны нам, и фиксы пойдут минорными релизами 0.1.x):

- `B-14-01..05` — пять багов, которые всплывут при первом боевом прогоне на реальной книге автора и зафиксируются через `/book:evolve` (детали — в [`docs/faq.md`](docs/faq.md), кластер 5 «Troubleshooting»).
- Voice profile inheritance (`extends:`) отложено в 0.2+ — пока каждый профиль самодостаточен, между книгами переносится через `/book:voice save-as`/`import`.
- Agent teams Claude Code (split-pane через `tmux`) на 0.1 не используется — оставлено как опциональная ветка для 0.2+.

**Что точно отложено на 0.2+:**

- Параллельный wave-based execution субагентов.
- Forks (`CLAUDE_CODE_FORK_SUBAGENT=1`).
- Mentor-режим для начинающих авторов.
- Workspaces (несколько книг в одной папке).
- Автоматическая генерация README книги / landing-страницы.
