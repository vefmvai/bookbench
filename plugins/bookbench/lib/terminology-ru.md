# Терминологическая политика BookBench

> **Назначение.** Глоссарий «англицизм-калька → русское соответствие» для авторов плагина и для агентов в пользовательских ответах. Предотвращает просачивание калек («скаффолдинг», «по дефолту» вместо «по умолчанию», «воркфлоу») в русскоязычный интерфейс плагина и в ответы агентов.
>
> **Этап создания.** 24 (релиз 0.3.2 — patch после live-теста «Спираль»). Фиксирует решение **D-40**.
>
> **Применение.** (1) Проверяется hook-скриптом `templates/hooks/anti-ai-cliche-lint.sh` на каждом Write/Edit субагентов. (2) Обязательная сверка для авторов плагина перед коммитом в `commands/` и `lib/`. (3) Раздел «Терминологическая политика» в шаблонах `templates/agent-guidelines/<role>/README.md` ссылается на этот файл.

---

## Граница применимости

**Подлежат замене** в:
- Пользовательских сообщениях команд (`commands/*.md` — текст, который видит автор книги).
- Текстах агентов в `agent-templates/*.md` (системные промпты, реплики автору).
- Описаниях команд (`description:` в frontmatter).
- Шаблонах гайдлайнов команды.
- Документации `docs/`, `README.md`, `CHANGELOG.md` (новые записи; исторические записи — не правим).

**НЕ подлежат замене** (технические термины фреймворка, оставляем как есть):
- Имена полей YAML/JSON (`default`, `workflow`, `addressing_mode`).
- Имена команд и подкоманд (`/bookbench:start`, `/bookbench:research-format`).
- Имена скиллов и субагентов (`book-writer`, `book-editor`, `voice-builder`).
- Frontmatter и идентификаторы.
- Английские заголовки служебных файлов (`# Book project`).
- Машинные API-метаданные (`description` в `manifest.json` — на английском по D-24).

## Термины, которые ЯВНО оставляем

Эти заимствования закрепились в русском языке и не имеют краткого русского аналога:

| Термин | Почему оставляем |
|---|---|
| лонгрид | нет краткого русского аналога; «длинная статья / большой материал» — описательно, не термин |
| фреймворк | устоявшийся технический термин; «каркас» в контексте программного обеспечения теряет точность |
| коуч / коуч-режим / коуч-диалог | устоявшийся (хотя и в коммерческом контексте); смысл «партнёрский расспрос», для которого «наставник» / «тренер» — неточно |
| skill / skills (имена файлов и параметров) | технический идентификатор Claude Code |
| subagent / sub-agent | технический идентификатор Claude Code |
| markdown | устоявшийся технический термин |
| frontmatter | технический термин формата YAML+Markdown |

## Правила линта

Hook-скрипт `templates/hooks/anti-ai-cliche-lint.sh` (расширен в этапе 24) применяет:

- **Уровень «блок» (exit 1):** калька попала в текст — Write блокируется. Применяется к: `скаффолдинг|скаффолд|дефолт|по дефолту`.
- **Уровень «предупреждение» (exit 0 с warning):** калька попала в текст — выводится предупреждение, но Write пропускается. Применяется к остальным кейсам из таблицы.

Правила могут быть переопределены в книжных гайдлайнах (`.book/agent-guidelines/<role>/forbidden-phrases.md` → секция `# Allowed (overrides default)`).
