# Инварианты и переменные методологии BookBench

> Документ-разделитель «инвариант / переменная / mixed» для всех методологических пунктов, собранных в карточках этапа 02 (`RESEARCH_NOTES.md` → раздел «Этап 02 — Методология больших текстов»). Цель — дать **чёткий контракт** между **базовым скиллом-методологом** (инжектируется во все писательские субагенты) и **жанровым скиллом-ресёрчером** (генерирует методологию on-demand под конкретную книгу). Без этого контракта на этапах 09 и 12 будет путаница «что куда складывать».

## Как читать таблицы

- Колонка «Карточка» — ID карточки в `RESEARCH_NOTES.md` (например, `T5.2`).
- Колонка «Категория» — `инвариант` / `переменная` / `mixed` (так же как в самой карточке).
- Колонка «Куда идёт» — конкретный артефакт BookBench (базовый скилл, скилл-ресёрчер, hook, шаблон роли).
- Колонка «Однострочное обоснование» — почему именно так классифицировано.

## 1. Инварианты (базовый скилл-методолог)

> Эти пункты верны для **любой** большой книги. Войдут в `.skill.md` базового скилла-методолога (этап 12), который инжектируется через `skills:` в писательские субагенты по умолчанию.

| Карточка | Пункт | Категория | Куда идёт | Обоснование |
|----------|-------|-----------|-----------|-------------|
| T1.5 | «Структура — отдельная фаза перед drafting'ом; ТЗ главы со схемой связей» | инвариант | базовый скилл → секция «Structure-First» | McPhee на десятках книг показал универсальность; работает и для нон-фикшн, и для fiction |
| T2.1 | «Между соседними разделами должна быть явная причинно-следственная связка (plot connector)» | инвариант | базовый скилл → секция «Coherence between sections»; чеклист редактора | Forster: без causality книга разваливается; правило универсально |
| T2.2 | «Red thread keywords: список + чеклист появления в каждой главе» | инвариант | базовый скилл; реестр у стратега и редактора (`memory: project`) | Roy Peter Clark, tool 26; универсально; пересекается с уникальностью реестров |
| T2.3 | «Редактор обязан читать соседние главы перед line edit текущей» | инвариант | дизайн субагента-редактора (этап 10): `tools: Read` всех глав, явное правило в системном промпте | Murray: «глаза читателя» возможны только при сквозном прочтении |
| T2.4 | «Два уровня связности: cohesion (line edit) + coherence (developmental edit)» | инвариант | базовый скилл; чеклисты на двух уровнях редактуры | Williams: эта модель — стандарт university composition; различие универсально |
| T3.1 | «Установка SFD: писатель пишет до конца, не вылизывая; полировка — задача редактора» | инвариант | системный промпт писательского субагента | Lamott: SFD — единственный способ закончить большой текст; работает в любом жанре |
| T3.2 | «−10% rule: между draft и edit текст сокращается на 10%» | инвариант | системный промпт редактора-субагента (developmental или line) | King: количественная цель против разводнённости; нарушается осознанно, но дефолт — сократить |
| T3.3 | «Четыре ментальных режима редактуры (структурный / стиль / голос / полировка) — разные операции» | инвариант | дизайн редакторов: либо один с режимами, либо четыре отдельных | McPhee + EFA подтверждают; универсально для проф-уровня |
| T3.4 | «UX: всегда есть следующий маленький шаг — не давать автору застрять» | инвариант | дизайн папки книги (этап 06), микро-цикл (этап 11) | Pressfield: Resistance универсален; UX-инвариант |
| T3.5 | «Микро-цикл главы делится на блоки, не глава-как-атом» | инвариант | дизайн микро-цикла (этап 11) | Boice: эмпирически daily writing > binge writing |
| T4.1 | «Четыре уровня редактуры: developmental / line / copy / proof — отдельные режимы» | инвариант | базовый скилл → секция «Editing levels»; дизайн редактора | EFA / Saller / King — конвергентно подтверждают; жанро-независимо |
| T4.2 | «Omit needless words: copy edit убирает лишнее по чеклисту маркеров» | инвариант | hook PostToolUse у редактора | Strunk & White, общий принцип ясности |
| T4.3 | «Редактор различает hard errors (правит) и taste preferences (флагирует комментом)» | инвариант | системный промпт редактора | Saller: универсальное проф-правило, защищает голос автора |
| T4.4 | «Copy editor отсылает к внешнему stylebook, не к интуиции» | инвариант | архитектурное решение этапа 12: stylebook как ресурс плагина | Принцип универсален; конкретный stylebook — переменная (см. ниже) |
| T5.1 | «Simplicity: убирать жаргон, наречия, надутые формулировки» | инвариант для нон-фикшн / научпопа | базовый скилл → секция «Nonfiction simplicity» | Zinsser: универсальный нон-фикшн принцип; не применяется к художественному голосу |
| T5.2 | «Curse of knowledge: эксперт не помнит каково это — не знать; нужен бабушкин тест» | инвариант | системный промпт писателя научпопа; gate в микро-цикле | Pinker: универсально для любого автора-эксперта |
| T5.5 | «Ladder of abstraction: каждый абстрактный тезис закрыт хотя бы одним конкретным примером» | инвариант для нон-фикшн | базовый скилл → секция «Concrete anchors» | Clark / Hayakawa: универсально для нон-фикшн; в fiction уже встроено в show-don't-tell |
| T6.1 | «28+ паттернов AI-writing запрещены в авторском тексте по умолчанию» | инвариант для всех LLM-черновиков | hook PostToolUse у писателя/редактора; skill `anti-ai-cliche` | Wikipedia + Humanizer — академически валидированный каталог |
| T6.2 | «Voice calibration: писатель читает примеры авторского текста при старте книги» | инвариант (механика) | дизайн писательского субагента; `memory: project` хранит voice profile | Универсальная механика; конкретный voice profile — переменная (книга/автор) |
| T6.2 | «Double-pass audit: после first rewrite — повторный проход с явным вопросом 'что выдаёт ИИ'» | инвариант | системный промпт писателя/редактора | Humanizer: эмпирически устойчиво улучшает результат |
| T6.3 | «You are an author, not an assistant: явно вывести модель из assistant-режима» | инвариант | системный промпт всех писательских ролей | Anthropic prompt-engineering practices; снимает большую часть AI-isms на старте |
| T7.1 | «План → секции → склейка (AgentWrite-pattern) — основа архитектуры» | инвариант | архитектурное решение, проходящее по этапам 06, 10, 11 | Bai et al. (LongWriter): академически валидировано |
| T7.3 | «Multi-role collaborative editing — лучше single-agent» | инвариант | философское ядро BookBench (PROJECT.md) | Schick et al. (PEER): академически валидировано |

**Итого инвариантов: 23.** Это будущий объём базового скилла-методолога — оценочно ~300–500 строк markdown. Уложится в лимит SKILL.md (рекомендация <500 строк, см. методичку автора по промпт-инжинирингу в `RESEARCH_NOTES.md`).

## 2. Переменные жанра (скилл-ресёрчер)

> Эти пункты **меняются от жанра к жанру**. Скилл-ресёрчер (этап 09) генерирует жанровый `.skill.md` под конкретную книгу, наполняя ровно эти параметры.

| Карточка | Пункт | Категория | Куда идёт | Обоснование |
|----------|-------|-----------|-----------|-------------|
| T1.2 | «Save the Cat! 15-beat sheet» | переменная | каталог скилла-ресёрчера для драматического fiction | Узкий жанровый шаблон голливудского screenwriting + romance |
| T1.3 | «IMRaD: Introduction-Methods-Results-Discussion» | переменная | каталог скилла-ресёрчера для академической монографии | Жанровая специфика академической публикации |
| T1.4 | «12 Acts (NovelCrafter / Vogler / Hauge)» | переменная | каталог скилла-ресёрчера для коммерческого fiction | Чисто жанровый шаблон fiction; не работает в нон-фикшн |
| T5.4 | «Feynman Technique: 4-step procedure для каждой ключевой концепции» | переменная (нон-фикшн / обучающие жанры) | скилл-ресёрчер для научпопа и обучающих жанров | Применимо там, где есть «концепции для объяснения»; в художественном — нет |
| T5.6 | «Narrative non-fiction arcs (Hart): чередование narrative/expositional lines» | переменная | скилл-ресёрчер для нарративного нон-фикшн (Sagan, Roach, Gawande) | Узкий жанровый шаблон; в чисто-explanatory нон-фикшн (Pinker) не работает |
| T5.7 | «3-act TED structure: hook + 3 ideas + memorable close» | переменная (научпоп / public-intellectual writing) | скилл-ресёрчер для научпопа | Приём конкретного поджанра |
| T6.4 | «AI-isms — индикатор повестки» | переменная (positioning, не методология) | docs / README BookBench | Не корпус, а контекст |
| (новое) | Выбор stylebook (Chicago / APA / Розенталь / Мильчин) | переменная | скилл-ресёрчер по языку и регионалу книги | T4.4 inv-принцип, но конкретный stylebook — переменная |

**Итого переменных: 8.** Это объём «жанрового слота», который заполняет скилл-ресёрчер. У ресёрчера будет шаблон с пустыми секциями, заполняемыми по жанру.

## 3. Смешанные случаи (mixed)

> «Общий принцип + жанровый параметр». Базовый скилл-методолог даёт **принцип**; скилл-ресёрчер уточняет **параметр** под жанр.

| Карточка | Пункт | Принцип (инвариант) | Параметр (переменная) | Куда идёт |
|----------|-------|--------------------|-----------------------|-----------|
| T1.1 | Pyramid principle | «Top-down: governing thought + supports + evidence» | Количество саппортов (3–4 для научпопа vs 1–2 для философского нон-фикшн), их типы | Принцип → базовый скилл; параметр → скилл-ресёрчер |
| T5.3 | SUCCESs (Made to Stick) | «Каждая ключевая идея использует ≥2 атрибута из SUCCESs» | Конкретные пропорции (emotional vs concrete) — переменная жанра | Принцип → базовый скилл (универсально для нон-фикшн); параметр → скилл-ресёрчер для интенсивности |
| T5.5 + T5.1 | Плотность примеров и ladder steps | «У каждого абстрактного тезиса есть якорь внизу лестницы» | Плотность примеров: научпоп ≈ 2–4 на главу; философский нон-фикшн ≈ 1; нарративный научпоп ≈ 1 history-сцена + 2–3 пояснения | Принцип → базовый скилл; параметр → скилл-ресёрчер по жанру |
| T7.2 | LongBench-Write бенчмарк | «Качество long-form оценивается по длине + N критериям» | Конкретные критерии и веса под жанр | Принцип → этап 15 (тестирование); параметр → жанровый профиль |
| (общий) | Voice profile | «Voice calibration: читать примеры авторского текста на старте» (T6.2) | Конкретный voice profile конкретной книги/автора | Принцип → базовый скилл; параметр → `memory: project` писателя для конкретной книги |

**Итого mixed: 5.**

## 5. Что не вошло (и почему)

- **Маркетинг и упаковка книги** (hook, blurb, cover) — это методология **продукта**, не текста. Переходит в этап 16 и в дизайн субагента-маркетолога (этап 10), но не в скилл-методолог.
- **Длина сессии и ритм работы автора** — UX-инвариант, не методологический; влияет на этапы 06 и 11.
- **Конкретные русскоязычные правила** (Розенталь, Мильчин) — **отложено на этап 12** (наполнение скиллов после дизайна архитектуры). На этапе 02 — только принцип «копи-редактор отсылает к stylebook».
- **Художественный fiction (12 acts, beat sheets)** — отложено в каталог скилла-ресёрчера; глубоко не разбираем, потому что первый поддерживаемый жанр BookBench — научпоп.

## 6. Сигналы для следующих этапов

**Этап 09 (дизайн скилла-ресёрчера жанра):**
- Шаблон жанрового `.skill.md` должен иметь **8 переменных секций** (см. таблицу 2) + **5 параметрических полей** для mixed (см. таблицу 3).
- Скилл-ресёрчер при генерации заполняет ровно эти секции.

**Этап 12 (наполнение скиллов):**
- Базовый скилл-методолог собирается из 23 инвариантов (см. таблицу 1).
- Целевой объём — ~300–500 строк markdown.
- Структура — 7 секций по T1–T7.

**Этап 11 (микро-цикл главы):**
- Hook PostToolUse у писателя — корпус анти-ИИ-клише (T6.1, T6.2).
- Установка системного промпта писателя — «author voice, not assistant» (T6.3).
- В цепочке стратег → писатель → редактор зашиты T1.5, T2.1, T3.1, T3.2, T4.1.

**Этап 10 (координатор и субагенты):**
- Системные промпты редактора, стратега, фактчекера используют инварианты T2.3, T2.4, T3.3, T3.4, T4.3.
- Каждый субагент имеет `skills: [base-methodology]` минимум.
