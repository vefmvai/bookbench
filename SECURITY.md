# Политика безопасности

## О поверхности атаки

BookBench — фреймворк для написания текстов в Claude Code. Он работает только с локальными markdown-файлами (главы книги, реестры памяти, гайдлайны команды агентов), не подключается к внешним сервисам в фоновом режиме и не обрабатывает секреты или платёжные данные. По дизайну поверхность атаки минимальна; реалистично возможные уязвимости лежат в трёх местах:

- **Hook-скрипты.** `bookbench/templates/book/.claude/hooks/anti-ai-cliche.sh` и аналогичные скрипты выполняются автоматически при `Write` инструментах. Уязвимость в bash-инъекции или парсинге путей могла бы дать атакующему контролируемое выполнение через подсунутый специально подготовленный текст главы.
- **Логика evolver.** `bookbench-evolver` читает мета-файлы (`TUNING-LOG.md`, `REJECTIONS-LOG.md`, гайдлайны, конфиг) с целью предложить правки в дефолты плагина. Структурные гарантии приватности (`disallowedTools` для запретных путей) — критичны; их обход — потенциальная уязвимость.
- **Импорт чужих материалов.** `/bookbench:import` принимает посторонние markdown-файлы (`inputs/`). Заведомо вредоносный prompt-injection в файле, оформленном как «черновик главы», теоретически может попытаться повлиять на поведение субагента-классификатора. Smoke-тесты и чёткие границы протокола `import-classification-protocol.md` снижают риск, но не исключают его полностью.

Всё, что вне этих трёх областей (написание тела глав, голос автора, реестры уникальности), не связано с безопасностью в строгом смысле — это про качество, не про vulnerability.

## Поддерживаемые версии

| Версия | Поддержка |
|--------|-----------|
| 0.1.x  | да        |

На момент 0.1.0 поддерживается только текущая ветка. Backports на старые минорные версии не делаем до выхода 0.2.

## Куда сообщать об уязвимости

**Рекомендуемый канал — приватные GitHub Security Advisories:**
[https://github.com/vefmvai/bookbench/security/advisories/new](https://github.com/vefmvai/bookbench/security/advisories/new)

Этот канал даёт сразу несколько преимуществ: переписка не публична до раскрытия, можно создать приватный draft-патч, GitHub автоматически выделяет CVE при необходимости.

**Резервный канал** — приватный issue с тегом `security` в [https://github.com/vefmvai/bookbench/issues](https://github.com/vefmvai/bookbench/issues). Используйте его, если по какой-то причине Security Advisories вам недоступны.

**Не сообщайте об уязвимостях через обычные публичные issues, pull request или discussions.**

## Что произойдёт после получения отчёта

- Best effort — ответ в течение **7 дней** на изначальное сообщение. SLA нет (BookBench — open-source проект сообщества, не коммерческий продукт).
- Если уязвимость подтверждена, мы согласуем дату публичного раскрытия и план фикса.
- При закрытии уязвимости — упоминание автора отчёта в `CHANGELOG.md` (раздел `### Security` соответствующей версии), если автор не возражает против публикации имени.

## Что не относится к безопасности

- Обычные функциональные баги (что-то работает не так, как описано в документации) — открывайте обычный issue с тегом `bug`.
- Замечания по качеству текста, генерируемого субагентами, или по корректности методологии — это improvement / feedback, не security.
- Запросы на новые функции — discussions или issue с тегом `proposal`.
