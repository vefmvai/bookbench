# BookBench 0.3.0 — release notes

> Major-релиз. Переосмысление стартового онбординга и разделение четырёх измерений работы автора (`genre / style / format / audience`) как ортогональных первоклассных сущностей. Структурный рефакторинг терминологии `chapter` → `section` во всём коде. Релиз вырос из первого живого запуска `/book:start` в мае 2026 — четыре UX-проблемы стартового интервью + одна концептуальная развилка стали Milestone 2.

## Что сделано

**Коуч-режим `/book:start`.** Жёсткое 5-вопросное radio-интервью заменено на открытый коуч-диалог. Команда принимает свободное описание автора, голосовой ввод и приложенные файлы (drafts, voice-samples, заметки); агент анализирует вход + опционально вызывает `/book:import` автоматически; формулирует одну гипотезу понимания «формат — X, ближайший жанр — Y, аудитория — Z, метка стиля — B1/B2/B3» с подтверждением автора. Реализация — inline в `commands/start.md` с физическим выносом коуч-промпта в `lib/start-coach-prompt.md` (433 строки, 4 коуч-сборки по `matching-design.md` §§ 3.1–3.7). Архитектурное решение D-33 (без 11-го субагента; состав команды остаётся 9 субагентов + voice-builder Skill).

**Четырёхмерная модель работы автора (D-30).** Четыре ортогональные первоклассные сущности — `genre / style / format / audience`. Жанр отвечает на «что» (научпоп / детектив / диссертация); формат — на «в какой форме упаковано» (статья / лонгрид / книга / монография / диссертация); стиль — на «каким голосом» (через скилл `voice-profile` + `voice-builder`); аудитория — на «для кого» (свободный текст-портрет, не enum). Расширяемые библиотеки в `defaults.yaml` (5 пресетов форматов, `compatible_formats` ко всем 4 жанрам) + ресёрч-команды `/book:research-genre` и **новая** `/book:research-format` для произвольных пресетов. Style собирается отдельно через `voice-builder` с отлётом до первой секции — TOV-08 сохранён дословно.

**Рефакторинг `chapter` → `section` во всём коде** (~150 файлов, D-31). Переименована директория `templates/book/chapters/` → `templates/book/sections/`, 9 slash-команд (`/book:write-chapter` → `/book:write-section` и т.д.), поля `current_chapter` → `current_section`, `chapter_loop` → `section_loop`. Адаптивная подстановка слов «глава / раздел / часть» в диалогах с автором — через `formats.<format>.section_word` + 5-строчный MUST-блок в каждом из 10 субагентов. В технических контекстах (имена файлов, путей, полей) везде `section`. Без deprecation aliases (D-32 — у нас нет инициализированных книг 0.2.x).

**Закрыт непонятный вопрос «когда глава готова».** Дефолт `workflow.completion_format: editor_pass_plus_author_approval` зафиксирован в `templates/book/config.yaml`. Меняется через `/book:config`.

## Что сделать пользователю

Чистая переустановка (структура `.book/` несовместима с 0.2.x):

```
/plugin uninstall bookbench@bookbench
/plugin marketplace remove bookbench
/plugin marketplace add vefmvai/bookbench
/plugin install bookbench@bookbench
/reload-plugins
/book:doctor   # должно показать BookBench 0.3.0
```

Если у вас уже есть инициализированная книга 0.2.x — см. секцию «Обновление с 0.2.x на 0.3.0» в `docs/upgrade-guide.md`.

После установки в новой папке книги: `/book:start`. Никаких radio-вопросов — просто опишите свободно, что вы хотите написать; голосом или текстом; можно сразу приложить наброски, заметки или фрагменты глав — агент их прочитает и задаст один уточняющий вопрос на каждое из четырёх измерений. Это и есть главное визуальное отличие 0.3.0 от 0.2.x.
